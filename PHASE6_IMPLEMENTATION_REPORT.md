# Phase 6 Implementation Report

## Executive Summary

Phase 6 adds immutable experiment tracking and reproducibility controls around
the existing EGX AI Trader engine. The trading engine, indicators, thresholds,
entries, exits, portfolio sizing, market regime logic, and AI ranking formula
were not changed.

Each Scan and user-facing Backtest now creates a unique directory under
`reports/RUN_ID/`. Legacy files in `reports/` continue to be written for
backward compatibility, while every new Run folder retains an immutable copy
of the inputs, environment, model identity, metadata, and generated artifacts.

## Architecture Changes

### Experiment lifecycle

`services/experiment_tracking.py` introduces two components:

- `ExperimentRun`: creates unique Run IDs, records snapshots and versions,
  saves canonical artifacts, captures legacy reports, writes the run README,
  and records completed or failed lifecycle state.
- `RunRepository`: lists and reads historical runs, compares saved runs without
  recalculating trades, exports ZIP archives, and performs path-validated Run
  deletion.

The tracking layer is passive. It receives completed Scan/Backtest results and
does not participate in signal generation, AI inference, ranking, portfolio
selection, sizing, or exits.

### Run directory schema

Every Run directory contains:

- `settings_snapshot.json`
- `environment.json`
- `model_info.json`
- `run_metadata.json`
- `README.md`
- Run-specific CSV reports

Backtests additionally produce canonical files:

- `summary.csv`
- `trade_log.csv`
- `equity_curve.csv`
- `daily_returns.csv`
- `yearly_metrics.csv`
- `failed_symbols.csv`

Existing Walk-Forward, AI comparison, risk-overlay, stress-test, bootstrap, and
legacy Backtest reports are copied into the Run directory when they are
generated by that run.

### Recorded provenance

Run metadata records:

- Run ID, type, status, timestamps, and execution duration
- mode, strategy identity, AI mode, and Walk-Forward status
- date range, capital, commission, slippage, and deterministic seed
- total, successful, and failed symbols with failure details
- Git hash when the working tree is accessible
- Python version, platform, executable, and installed packages
- AI model SHA-256 and metadata
- content-derived dataset, feature, and Walk-Forward versions
- summary metrics and artifact manifest

JSON writes are atomic. A same-second Run ID collision receives a deterministic
numeric suffix. Existing artifacts inside a Run cannot be overwritten through
the tracker.

### Dashboard

Two additive Streamlit pages were added:

- **Run History**: history table, Run selection, report viewing, confirmed
  deletion, comparison selection, and complete ZIP export.
- **Compare Runs**: side-by-side metrics, equity curves, monthly returns, and
  yearly returns for two saved Backtests.

The Dashboard and Settings pages now display the Run ID produced by a Scan or
Backtest. Existing navigation entries and controls remain available.

## Future Recommendations

1. Add a forward-test Run type using the same immutable metadata schema.
2. Add a retention policy based on age/storage size, with deletion always
   requiring explicit user confirmation.
3. Store data-provider response manifests or local dataset snapshots when
   licensing and storage constraints permit byte-for-byte market-data replay.
4. Add optional signing of `run_metadata.json` and artifact checksums for
   tamper evidence.
5. Add a lightweight process lock if multiple Streamlit workers are introduced;
   current Run IDs are thread-safe within one application process.
6. Add CI execution of `requirements-dev.txt` and the full test suite on every
   code change.
