## 3. The reports problem — the one real policy defect

**`reports/` is entirely gitignored** (`.gitignore:82`, with only `reports/eodhd/` excepted).

That is correct for generated artifacts. It is wrong for the documents currently sitting there:

| Path | Nature | Currently | Should be |
|---|---|---|---|
| `reports/.../ORB_FIRST_PULLBACK_ARCHITECTURE_AUDIT.md` | Hand-authored design contract | ignored | **MOVE** to `docs/audits/strategies/orb_first_pullback/` and commit |
| `reports/.../ORB_FIRST_PULLBACK_DATABASE_SCHEMA.md` | Hand-authored schema contract | ignored | **MOVE** and commit |
| `reports/.../ORB_FIRST_PULLBACK_STATE_MACHINE.md` | Hand-authored — the Phase 2B specification | ignored | **MOVE** and commit |
| `reports/.../ORB_FIRST_PULLBACK_IMPLEMENTATION_PLAN.md` | Hand-authored plan | ignored | **MOVE** and commit |
| `reports/.../ORB_FIRST_PULLBACK_UI_WIREFRAME.md` | Hand-authored | ignored | **MOVE** and commit |
| `reports/.../ORB_FIRST_PULLBACK_DATA_READINESS.md` | Phase 1 narrative | ignored | **MOVE** and commit |
| `reports/.../phase2a/ORB_PHASE2A_DATA_READINESS.md` | Tool-generated, reproducible | ignored | **KEEP IGNORED** — correct |
| `reports/.../phase2a/ORB_RUBIX_VOLUME_SEMANTICS.md` | Tool-generated | ignored | **KEEP IGNORED** |
| `reports/.../phase2a/orb_capabilities.json` | Tool-generated | ignored | **KEEP IGNORED** |
| `reports/.../phase2a/orb_session_coverage.csv` | Tool-generated | ignored | **KEEP IGNORED** |
| `reports/.../phase2a/orb_minute_coverage.csv` | Tool-generated | ignored | **KEEP IGNORED** |
| `reports/.../phase2a/orb_volume_quality.csv` | Tool-generated | ignored | **KEEP IGNORED** |
| `reports/.../phase2a/orb_opening_range_readiness.csv` | Tool-generated | ignored | **KEEP IGNORED** |
| `reports/.../phase2a_review/*` (this review, 8 files) | Hand-authored | ignored | **MOVE** to `docs/audits/strategies/orb_first_pullback/phase2a_review/` and commit |

**Why this matters.** Phase 2B is specified by `ORB_FIRST_PULLBACK_STATE_MACHINE.md` and
`ORB_FIRST_PULLBACK_DATABASE_SCHEMA.md`. Both live in a directory that Git will never track.
If this worktree is removed, the contracts Phase 2B is meant to implement vanish with it, while
the code that implements them survives. The generated readiness artifacts are exactly the
opposite case — they are reproducible byte-for-byte from the Rubix database, so ignoring them is
right.

The repository already has the correct home: `docs/audits/strategies/` is tracked and holds the
comparable documents for the other strategies. The split should follow the existing convention —
**hand-authored contracts under `docs/`, tool output under `reports/`.**

These deliverables were written to the path the review brief specified. They should be moved
before commit; no content change is needed.
