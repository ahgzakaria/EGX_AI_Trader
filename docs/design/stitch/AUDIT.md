# Audit of the Stitch import

*2026-09-12 · against `docs/design/stitch/imported/` · 12 screens + 1 design system*

**What is being audited, and what that changes.** These files are Tailwind HTML
generated by Stitch. **None of them ship.** The app is Streamlit, and this HTML
is a specification that gets re-implemented as CSS inside `dashboard/ui.py`. So
the findings are weighted by whether a defect would *propagate into the app*, not
by whether it would matter in a web build. A blocking `<script>` in `<head>`
never reaches production here; a semantic colour that drifted from the spec does,
because I would copy it.

| | |
|---|---|
| ✅ OK | consistent, propagates safely |
| ⚠️ minor | fix during the token/typography pass |
| ❌ critical | would carry a defect into the app; fix before implementing |

---

## 1. ❌ Fonts — one screen is off the type system entirely

11 of 12 screens load the IBM Plex family. **`07-watchlist` loads `Cairo` and
`Inter` instead** — a different Arabic face and a different Latin face from every
other screen and from the design system spec.

Three screens (`02-daily-dashboard`, `09-ai-analysis`, `10-system-health`) load
IBM Plex Sans Arabic and Mono but **not IBM Plex Sans**, so Latin prose on those
screens falls back to the browser default.

No inline `font-family` overrides anywhere — that part is clean.

## 2. ⚠️ Heading sizes — no shared semantic scale

Heading depth varies from `h1, h2` (`08-stock-details`) to `h1…h4`
(`06-sector-liquidity`, `10-system-health`, `11-settings-backtest`). Sections at
the same semantic level are marked up at different levels on different screens.

Sizing is otherwise consistent in method — Tailwind scale classes, only two
literal `text-[Npx]` overrides in the whole import (`04`, `05`).

## 3. ❌ Colours — the spec's semantic palette was overwritten by Tailwind defaults

The design system fixes the semantic colours as `#34d399` green, `#f87171` red,
`#60a5fa` blue, `#fbbf24` amber. Several screens declare Tailwind's own defaults
in their `tailwind.config` instead:

| spec | substituted |
|---|---|
| `#34d399` | `#10b981` (×6) |
| `#f87171` | `#f43f5e` (×4), `#ef4444` (×2) |
| `#60a5fa` | `#3b82f6` (×6) |
| `#fbbf24` | `#f59e0b` (×7) |

Also off-spec: five undeclared near-black grounds (`#070b14` ×9, `#080d18`,
`#080d17`, `#080d16`, `#0b111c`) and three undeclared surface tints (`#1f2e4d`
×7, `#18243c`, `#1f2e50`).

`02-daily-dashboard` is the worst: **19 off-spec hexes**. `03-swing-breakout` and
`04-breakout-watch` are perfectly on-spec — zero drift.

Arbitrary Tailwind values (`[#hhhhhh]`) appear 17× in `11-settings-backtest`,
14× in `05-confirmed-breakout`, 8× in `07` and `09`.

## 4. ⚠️ Animations — present everywhere, and all of it must be dropped

Every screen carries `transition` classes (4 to **55** per screen), `animate-*`
utilities (1–9), and `10-system-health` has a `@keyframes` block. The brief
banned animation because Streamlit cannot do it.

This is not a defect in the design — it is Stitch's default output — but it is a
**porting hazard**: these classes must be discarded rather than translated, and
the hover states they decorate must be re-expressed as static CSS.

## 5. ⚠️ Interactive states — hover is good, focus is not

Hover states are dense and consistent (27–73 per screen). **Focus states are
absent on four screens** (`03`, `06`, `10`, `12`) and sparse on most others
(1–2). `05-confirmed-breakout` (7) and `09-ai-analysis` (8) are the only ones
that treated focus seriously. Keyboard use would be invisible.

## 6. ✅ Spacing — consistent

The 4px scale from the spec holds across the import. No mixed unit systems for
the same purpose.

## 7. ⚠️ Z-index — undocumented, and one ladder is arbitrary

Most screens use one or two values. `03-swing-breakout` uses **five** (`z-5`,
`z-10`, `z-15`, `z-20`, `z-30`) with no stated meaning. `z-50` appears on five
screens for what looks like the same role as `z-30` on others.

Low impact: Streamlit owns its own stacking context and almost none of this ports.

## 8. N/A Responsive — deliberately out of scope

Breakpoint use is inconsistent (`06-sector-liquidity` has 34 breakpoint classes;
`02`, `04`, `05`, `07`, `12` have none). **This is not a finding.** The app is
desktop-only at 1640px by explicit decision, and the template's 375px/768px
requirement does not apply. Checked at 1280 / 1640 / 1920 instead, in pass 7.

## 9. ⚠️ Component structure — no images, few labels

Zero `<img>` elements in the entire import, so no alt-text findings. Icon-only
buttons are the gap: `07-watchlist` has **47 buttons and 0 `aria-label`**;
`10-system-health` 13 and 0; `11-settings-backtest` 9 and 0. Across all 12
screens there are 128 buttons and 4 labels.

## 10. ⚠️ Accessibility — contrast is fine, focus and labelling are not

Text tiers (`#e6edf7` / `#8ea1bd` / `#5a6f8c`) on the surface ladder pass at the
sizes specified. The failures are §5 (no focus rings) and §9 (unlabelled icon
buttons). Real `<button>` elements are used throughout rather than clickable
divs — that part is right.

## 11. N/A Performance — nothing here is shipped

Tailwind is loaded from CDN in `<head>` on all 12, which would be a finding in a
web build. No images, so no lazy-loading finding. Unused CSS is irrelevant: none
of this CSS reaches the app.

## 12. ✅ Code hygiene — clean

Zero `console.log`. Zero `TODO` / `FIXME`. No dead code of note.

## The seven rules — how well each screen actually expresses them

This matters more than everything above, because these rules are why the redesign
exists.

| rule | screens honouring it |
|---|---|
| Stale is not current (session stated) | **12 / 12** ✅ |
| Tabular numerals | **11 / 12** ✅ (`12-shell` missing) |
| Provenance on the number | **9 / 12** ⚠️ |
| Unknown is not zero | **7 / 12** ⚠️ |
| Bilingual `dir=` islands | **8 / 12** ⚠️ |
| `<bdi>` around bidi numbers | **5 / 12** ⚠️ |
| Advisory is not an instruction | **5 / 12** ⚠️ |
| **Three states, never two** | **2 / 12** ❌ |

**The three-states failure is the critical one.** Only `08-stock-details` and
`10-system-health` render an UNAVAILABLE state alongside PASS/FAIL. Everywhere
else a check that could not run is indistinguishable from one that passed — which
is precisely the defect that caused this project's market filter to report `PASS`
for years while it was inert, and the reason rule 5 was written into the brief.

`08-stock-details` is the reference implementation: it is the only screen that
satisfies **all eight** measured properties.

## Verdict

| | count |
|---|---|
| ✅ OK | 3 |
| ⚠️ minor | 7 |
| ❌ critical | 3 — fonts (§1), colour drift (§3), three states (seven rules) |
| N/A | 2 |

The import is good work. The design system spec is genuinely usable and honours
the Streamlit constraint, the bilingual rules and the density brief. The three
critical findings are all *consistency* failures between screens rather than bad
design — which is exactly what a token pass fixes.
